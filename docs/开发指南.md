# 开发指南 · 功能与代码位置对照

> 面向：要改这个编辑器的人（或 AI）。
> 读法：先看 §1~§2 建立整体印象，改什么就去 §3 找对应的文件，§4 是几个必须懂的机制，§5 是常见任务的做法。
> 代码与本文冲突时**以代码为准**，并顺手把本文改对。

---

## 1. 一分钟看懂整体

三个程序集 + 一个 Godot 工程：

```
            ┌─────────────── Editor（Godot 4.7.2 .NET）───────────────┐
            │  GDScript：界面 / 绘制 / 交互 / 面板（不要写业务规则）   │
            │      ↕ 只通过下面两个 C# 桥                            │
            │  EditorBridge.cs        MapExportBridge.cs             │
            └──────┬──────────────────────────┬──────────────────────┘
                   ↓                          ↓
            ┌────────────┐            ┌──────────────┐
            │  SimCore   │ ←────────  │  MapExport   │
            │ 仿真核(纯C#)│            │ 格式转换(纯C#)│
            └────────────┘            └──────────────┘
```

**为什么这么分**：路网校验、转向推导、冲突判定、信号相位、计分这些"对错有唯一答案"的逻辑必须只有一份实现，
而且要被单测覆盖 → 放 C#。界面怎么画、按钮点下去什么反应 → 放 GDScript。

**规矩**：GDScript 里**不许**重新实现放行判定 / 冲突检测 / 校验规则。需要就在 `EditorBridge.cs` 里加一个方法。

---

## 2. 启动顺序（调试时有用）

1. `Editor/project.godot` 的 autoload 挂上 `EditorApp`（`scripts/app/editor_app.gd`）
2. `Main.tscn` 加载：`GridCanvas`（画布）+ `EditorCamera` + 两个 Bridge + `CanvasLayer` 下的一堆 UI
3. `EditorApp._ready()`：装中文化 → 应用主题 → 读布局 → 恢复最近文件 → 检查崩溃残留
4. 各 UI 面板 `_ready()` 里连 `EditorApp` 的信号

出问题时最常看的两处：**`EditorApp._ready()`** 和 **`Main.tscn` 的节点树**。

## 4. 五个必须懂的机制

### 4.1 `Doc` 零信号，变更统一广播

`Doc` 是纯数据类，**故意不发信号**。原因：一次操作常常连续改好几处，逐条发信号会让面板重建几十次。

变更后调用 `doc.touch()`；`EditorApp` 每 0.25 s 比一次 `content_signature()`，变了就发 `content_changed`（带 0.08 s 防抖）。

**不要**给 `Doc` 加信号，也**不要**在面板里自己写轮询。

### 4.2 三层重绘靠签名

`RoadLayer` / `DecoLayer` / `GridCanvas` 的 `_process` 各比一个签名，变了才 `queue_redraw()`。

| 层 | 签名 |
| --- | --- |
| `road_layer` | 结构签名（数量/id/类型）+ 坐标签名（x/y/尺寸）+ 视图签名（相机/图层开关） |
| `deco_layer` | `_state_sig()` |
| `grid_canvas` | 网格签名（缩放/偏移/图层） |

**新增任何影响画面的状态，必须加进对应签名**，否则"数据变了但画面没动"。

★ 陷阱：改**值**（不是增删）要进坐标签名；而且别只靠 `x * k` 这种矩项——对象常落在原点，矩项恒为 0。

### 4.3 面板指纹只放"印出来的字"

`property_panel._fingerprint_of()` 决定 `content_changed` 来了要不要重建这一屏。

**只放会改变行文本/结构的信息**。不要塞 `content_signature()` 那种全局粗签名——它含专业档 revision，
结果是"改一个 SUMO 开关整块面板闪一下"。

同理：`_outline_sig()` 只放数量 + id + 类型/端点/素材，**不含坐标、不含专业档**。

### 4.4 两个桥接

| 桥 | 职责 | 约定 |
| --- | --- | --- |
| `EditorBridge.cs` | 校验 `.spmap` / 冲突对 / 推导转向 / 建议相位 | 只做**查询**，不搬数据；异常一律转成 `{ok:false, error}` |
| `MapExportBridge.cs` | 导出各格式 / 检测 netconvert / 探针 / 试跑 | 同上，且**长任务走后台 job + 轮询**（`Task.Run` + `Poll*`），不阻塞界面 |

GDScript 侧统一走 `EditorApp.get_bridge()` / `get_export_bridge()`。

### 4.5 导出的"临时文件 → 校验 → 落盘"

**绝不能直接写目标文件**。流程：

1. 序列化（在副本上 `renumber()` 成 0..N-1）→ 写 `user://_export_tmp.spmap`
2. 交 `EditorBridge.ValidateFile` 校验
3. **0 条 Error 才落盘**；有 Error 就中止，逐条打印 `[Error] 校验码 说明 @ 路径`
4. 写同目录 `.spdeco.json`
5. 若勾了 SUMO 格式：先跑**导出前体检**（`sumo_check_model.gd`）→ 有 Error 就跳过全部 SUMO 产物（`.spmap` / SHP 照常）
6. 生成 SUMO 各产物 → 再跑**导出后体检**（`SumoCheck.cs`）→ 有 Error 只报不删（文件已写）

体检结果统一并进 `EditorApp.validation_error_items`（格式 `{Code, Severity, Message, Path}`），
`Path` 用**文件 id**（`turns[12].sumo`），于是顶栏错误数、清单浮窗、点一条定位全部自动可用。

## 5. 常见任务怎么做

### 5.1 加一个快捷键

1. `grid_canvas.gd::_handle_global_key()`：`Ctrl+…` 放最上面的 `if e.ctrl_pressed` 分支，单键放 `match e.keycode`
2. **`help_panel.gd::KEYS` 同步加一行**（F1 表和键位提示条都读它）
3. 需要撤销的操作包在 `begin_edit/end_edit` 里

### 5.2 属性面板加一行 / 一个小节

```gdscript
_section("我的小节")                       # 可折叠
_add_row("字段名", _spin(初值, 最小, 最大, 步长, func(v: float): _set_xxx(v)))
_add_row("", _btn("按钮文字", _on_xxx))
```

- 控件一律走 `Clay.*` 或 `_btn/_spin/_check/_info/_wrapped` 这些 helper，别裸 `new()`
- 写入回调里：改 `Doc` → `begin_edit/end_edit`（一步撤销）→ `_refresh_later()`
- 卡片标题固定宽度 `UITokens.FIELD_W`，不要自己写宽度

### 5.3 给 `Doc` 加一个会被导出的字段

少一步就会"编辑期有、导出没有"或"撤销后丢"：

| # | 位置 | 要改什么 |
| --- | --- | --- |
| 1 | `Doc` 成员 | 加字段/表 |
| 2 | 增删改函数 | 维护它 |
| 3 | `Doc.snapshot()` / `restore()` | **两处都要加**（`duplicate(true)`） |
| 4 | `Doc._schema_dict()` | 加进导出 JSON。可选键要**条件写**，否则旧关卡过一遍编辑器就凭空多出空数组 |
| 5 | `Doc.from_json_text()` | 读回来，缺省值兼容旧文件 |
| 6 | `Doc._import_shape_error()` | key 列表要加，否则形状校验判文件坏 |
| 7 | `Doc._normalize_int_fields()` | 该是整数的转 int（米制坐标别强转） |
| 8 | `Doc.renumber()` | 含 id 引用必须一起重映射 |
| 9 | `Doc._export_copy()` | 导出副本要带上（**含计数器**） |
| 10 | `EditorApp.content_signature()` | 需要触发广播就加 |
| 11 | `road_layer._struct_sig()` / `_pos_sig()` | 影响画面才加（见 §4.2） |
| 12 | `property_panel` | `_panel_target()` / `_rebuild()` / `_fingerprint_of()` 三处加分支 |

**不要**为了加字段去改 `spmap-schema.md`（冻结）。

### 5.4 给 SUMO 专业档加一个字段

专业档和 `.spmap` 是两套链路，加字段只动专业档：

1. `docs/sumo-profile-schema.md` 先定 schema
2. `SumoProfile` 成员 + `defaults()`（默认值抽成常量）
3. ★ **`has_content()` 必须加**，否则"只改了这一项"时判成没有专业数据 → 导出根本不传
4. `clone()` / `equal()` / `signature()` 三处都要带
5. `to_dict()` / `from_json_text()` 写读对称，等于默认值就删键
6. `remapped()` 含 id 引用要一起映射，找不到的进 `orphans`
7. 数据层 model 加 `KEYS/LABELS/RANGES/UNITS` + `value()/set_value()`
8. 面板 `_build_*` 加行，回调 → `profile.touch()`
9. C# DTO 加 `[JsonPropertyName]`，接到生成器里
10. 补单测 + `qa_*.gd` 断言

**两个必踩的坑**：整型字段别存 float（JSON 写 `7.0`，C# 的 `int?` 会抛异常丢掉**整份**专业档）；默认值别写进文件。

### 5.5 加一条校验 / 体检规则

先判在哪一侧：

| 判据 | 放哪 |
| --- | --- |
| 只看 `.spmap` + `.sumo.json` 就够 | **导出前** `sumo_check_model.gd` |
| 需要真实产物（`linkIndex` / net 车道长度 / 冲突矩阵） | **导出后** `SumoCheck.cs` |

两侧产出格式一样：`{Code, Severity, Message, Path}`。
`Error` = 产物坏 / 数据丢（会拦 SUMO 产物）；`Warning` = 能生成但没配全。

## 7. GDScript 的坑（都踩过）

| 坑 | 症状 | 规矩 |
| --- | --- | --- |
| `var x := EditorApp.xxx` | autoload 与模式脚本构成编译依赖环 → `Cannot infer the type` → 连锁编译错误 → **autoload 变成空 Node**，之后所有 `EditorApp.xxx` 都是 Nil | 一律显式写类型 |
| `var x := <Variant>` | Parse Error（`JSON.parse_string()` 之类返回值是 Variant） | 用 `=`，或先 `as` 断言 |
| 新增 `class_name` 后没重建缓存 | 引用它的脚本 Parse Error | 加完先跑一次 `--headless --editor` |
| `@tool` 脚本碰 autoload | 编辑器里报空引用 | 先 `if Engine.is_editor_hint(): return` |
| 在 `_refresh()` 里 `await` 但调用处没 `await` | 断言跑在面板重建之前，表现为"明明改了却失败" | 调用处也 `await` |
| 容器里的控件补 `position`/`height` | 下一帧被重排打回去 | 只补 `modulate`/`scale` |
| `button_pressed = true` 后再手动 `emit` | 触发两次 | 赋值本身就会发信号 |

## 8. 术语表

| 词 | 含义 |
| --- | --- |
| **road** | 画布上拖出来的"一条路"（壳），展开成多条 lane |
| **lane** | 车道。`lane_index`（第几条）+ `lat_index`（横向位置，用于进口拓宽） |
| **turn** | 转向：某条进口车道 → 某条出口车道 |
| **signal / phases** | 某路口的相位方案；每个 phase 有 `duration` 与各 turn 的灯态 |
| **demand** | 交通需求曲线（分段的 时间→流量） |
| **island** | 二次过街的中央安全岛 |
| **PPM** | Pixels Per Meter，画布缩放换算 |
| **探针（probe）** | 临时跑一次 netconvert 拿到真实 link 表（`linkIndex` 由 netconvert 分配，界面自己算不出来） |
| **专业档** | `.sumo.json`，SUMO 专业模式的数据，与 `.spmap` 并列 |
| **覆盖层（override）** | 导出时按专业档改写 `net.xml` 属性，不改变 `.spmap` |
